# w1 agent_host: staged operator runbook

Nothing here runs until the owner says go. Pre-merge evidence: `bash tests/w1-agent-host-gate.sh` and `bash tests/w1-agent-host-selftest.sh`. The role rules are in CLAUDE.md (`agent_host` rules).

## Operator runbook

Nothing in this section runs before the user says go. Run from the repo root of the merged tree, from tmux, with `.vault_pass` present. Placeholders in angle brackets come from the vault or the PC and are never committed. Stop on the first failed check, undo with 7.7, do not start the next stage. A command whose expected result is a non-zero exit (step 0.5, the first command of stage H, a `grep -c` that must print 0, the port probes of stage E) is marked as such: run it on its own, never in a `&&` chain or under `set -e`.

### 0 Preconditions (all must be true; the user confirms the starred ones)

1. PR merged (section 11) and `git status` clean on the merged commit.
2. `*` Out-of-band console: the provider VNC or rescue path works (U3 of repo-final). Required before stage D, E and H.
3. `*` The user's decisions in section 9 recorded (defaults stand when the user stays silent).
4. `*` Permission to run the baseline snapshot, check and bench on the live host, and when (cpu pressure was 7 to 44 percent during scoping; the default `run` is about 8 minutes on a local shim, about 59 logins counted from the code, up to 0.8 GB, and each of its 30 transfers may take up to 120 s on the real path; it prints a projected total after the first transfer pair and stops itself at `W1_MAX_SECONDS`, default 900, P10). Ask before running it during an active phone session; it saturates the link the user's herdr session uses for about 25 s. Never start a `run` or a stage snapshot pair across minute 17 of an hour: the provider's hourly cron drops the page cache and runs `fstrim` then, which confounds the memory and IO numbers; compare a before and an after taken at the same minute offset.
5. Not within `agent_host_apt_timer_margin_minutes` (15) of the next elapse of `apt-daily.timer` or `apt-daily-upgrade.timer`: preflight P4 and the reboot guard refuse inside it; read `systemctl list-timers apt-daily.timer apt-daily-upgrade.timer` yourself before a stage (the times are randomised each cycle); and no `apt`/`dpkg` process running (stage A preflight reads it).
6. Open a root session now and keep it active: a second terminal in tmux holds `ssh root@<w1-host>` (independent break-glass; preflight P2 proves only that such a login can be opened, so stages D, E and H assert `agent_host_second_terminal`; keep it from idling out during a long run, for example with `ssh -o ServerAliveInterval=30`), and the controller identity used by Ansible can open a raw `ssh ubuntu@<w1-host> 'sudo -n true'` (preflight P10, which builds the same argv as the probes, 3.2).
7. `*` The console password rotation (user action b) is done and tested through the provider console before stage D, E and H, because that password is the break-glass of last resort and must not be the one stored in plain text in the cloud-init user-data. Paste no excerpt of the cloud-init files into the PR, the runbook output or a commit; the safe read form is in 9.2 (user action b).
8. `*` Dead-man timers are exercised once before they are relied on (preflight P11, below): the first real firing path would otherwise be the failure it exists for.

Before the real run open a root session now (`ssh root@<w1-host>`) and keep it active until ssh answers again after the reboot: the real run asserts `agent_host_second_terminal` (the `--check` run does not) and `shutdown -c` is run from that session.

Expected: the first run prints the pending kernel, the agent processes, the inhibitors, the scratch size and stops at the confirmation assert (rc non-zero by design: it is the dry run, run it on its own and do not chain it). The `--check` run reports the reboot task changed without rebooting and then runs the check engine. The real run reboots, waits, asserts (kernel equals target, `user@` active, linger yes, node_exporter and alloy active, reboot-required gone, watched sshd keys identical) and ends with the check engine exiting 0. Record: wall-clock until ssh answers, the printed sysctl delta, `W1_TARGET=$T tests/w1-agent-host-bench.sh snapshot after-reboot`, and the same bench `run`. Rows closed by the reboot: K01, K02, SE07 to SE09, the user-manager limit, boot persistence of every sysctl and of swap, zswap, `tcp_bbr` (`journalctl -b -g 'ordering cycle'` empty). Rollback: `shutdown -c` from the already-open second root terminal inside the 60 s window (new non-root logins are refused once `/run/nologin` exists, root is exempt and the open session needs no login, the reboot play); after it, provider rescue or VNC.

Optional one-shot GRUB fallback (the user's decision, decision 6; not part of the role): set `GRUB_DEFAULT=saved` in `/etc/default/grub` and run `update-grub`; `grub-set-default '<old-kernel-entry-id>'` makes the old kernel the saved default; `grub-reboot '<new-kernel-entry-id>'` boots the new one once (take both ids from `grep -E '^[[:space:]]*(menuentry|submenu)' /boot/grub/grub.cfg`, joining a submenu id and its entry id with `>` and no spaces). GRUB clears the one-shot entry before booting it, so a new kernel that panics after `10-panic.conf` applies, or hangs and is reset from the provider panel, comes back on the old kernel. After a good boot set the new kernel as the saved default again (or restore `GRUB_DEFAULT=0` and run `update-grub`), otherwise every later reboot keeps the old one. It does not recover a hang or an early panic that nothing resets (`kernel.panic` is 0 and no `panic=` is on the command line until `10-panic.conf` applies); then the provider console is the way back.

The settings gauge compares against the values and the id list the role rendered into its script, so after a rollback of another stage (for example `agent_host_net_congestion_control: cubic`) that setting reads 0, or the id list stays stale, until `--tags agent_host_reporting` re-renders the script; the timer running again never clears it, which is why every rollback row above that changes a gauge-reported setting ends with that tag (the firewall row too when `agent_host_ssh_enabled` is false, since `ssh_rollback_idle` then follows the firewall switch). The check rows `RS06` to `RS09` and `RS12` print `inconclusive` while the file is older than the owning config; the other `RS` rows read a hard 0 until the script is re-rendered. `agent_host_kernel_info` `newest` is the highest version directory under `/lib/modules` (`sort -V`), a plain informational label and not the kernel GRUB boots by default. `agent_host_reporting_settings_interval_seconds` is asserted between 30 and 300 because the panel treats a report older than 600 seconds as silent. Only `ssh_publickey_only`, `ssh_password_off` and `ssh_keepalive` read `sshd -T`, and a failed or timed-out `sshd -T` leaves them at 0 (fail closed for security settings). A `-e` run of a stage and its check must carry the same `-e`; once a durable key is committed neither needs it. The check engine's rows do not follow these switches unless a row says so (R11 and R12 carry no condition): after a durable rollback leave that domain out of `agent_host_check_domains`, and expect the full check to list some of its rows as failing (R11 does, R12 passes).

Failure handling: a failed stage leaves the host valid (every task file converges in tasks and is self-sufficient): re-run that stage's tag; the check names what is left (`HALF-APPLIED` shows disk ahead of runtime, `RUNTIME-ONLY` runtime ahead of disk). If the controller link dies during stage D or E the dead-man fires after 300 s; reconnect and run the check before trusting the host. An UNREACHABLE host is not rescued by `rescue:`: use the second terminal, then the provider console. A real run that stops at `pass -e agent_host_second_terminal=true` changed nothing: open the second terminal and run it again.


## Open decisions (each has a safe default that ships)


1. **Root SSH policy and hardening keys.** `PermitRootLogin` (keep `yes`: root key logins are in daily use and the root herdr-core depends on them; or `prohibit-password`; or `no`), `X11Forwarding no` (user question: no defect verified), `AllowAgentForwarding no` (breaks herdr's agent registration). Default: all unmanaged. To adopt one, add it to `agent_host_ssh_auth` and list it in `agent_host_ssh_unlocked_keys` (the stage asserts both).
2. **earlyoom.** Adopt or not; go-live after a dryrun period; thresholds `10,5` (owner's runbook: SIGTERM at 1196 MiB, SIGKILL at 598 MiB of 11960 MiB) versus `8,4`; whether claude is shielded (an avoided claude scores about 520, below alloy and node_exporter, so shielding is coherent only if the system daemons are avoided too); swap size 4096 MiB versus half of RAM clamped to 2-8 GiB (about 5980 MiB). The role refuses to resize an active swap file, so decide the size before the apply. Default: earlyoom off, swap 4096 MiB.
3. **Firewall.** Whether ufw and fail2ban exist on w1 at all (lockout risk, mosh UDP range, roaming phone addresses, a shared carrier address can be banned by fail2ban). Timing of the first enable: right after the reboot (no live flows, no stall) or live with the pre-warm (idle flows may stall until their application retries). Whether to attach a provider panel firewall as a second layer (manual, outside Ansible; it needs TCP 22 and the mosh range). Default: stage E not run.
